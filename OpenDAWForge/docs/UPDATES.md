# Application updates

**SETTINGS** offers Check now, Check at startup and an optional automatic-install toggle. Startup checking defaults on; automatic installation defaults off. Preferences are stored independently of projects in `LSFactory/update-settings.json`. An available update changes the toolbar button to UPDATE. Automatic installation waits until the project is saved, playback/recording is stopped, workers and auditioning are idle, and library/plugin/modal windows are closed.

The updater queries the public, official GitHub release feed over verified HTTPS. It compares numeric three-part versions, ignores drafts and selects only the exact platform installer filename under this repository's release-download URL. Published development prereleases are included because this application currently ships in that channel. It requires GitHub's SHA-256 asset digest and an exact bounded file size. Downloads run off the UI/audio thread, have connection/low-speed timeouts and a 128 MiB limit, use a unique partial file and are checked before caching. The cached file is checked again immediately before execution. Failure never launches an unverified file and never triggers an endless automatic retry loop; Check now allows a retry.

Windows uses the native Setup.exe, passes the existing program directory and waits for the old process to exit before installation, then relaunches the program. Linux requires a managed installer installation; its Installer.AppImage runs in extraction mode, waits for the old process, updates only managed program/launcher files and restarts the installed launcher. Personal projects, cached sounds, favourites and settings remain in their existing locations. The Mac release currently supplies a native ZIP rather than an installer, so use the release-page action there; automatic installation is disabled.

Programs older than this updater feature must be upgraded once using the new installer. Subsequent releases can be applied through SETTINGS. No account or cloud-library service is needed for application updates. GitHub API rate limits or network failures are reported in the settings panel and can be retried.

`--update-smoke-test <directory>` tests version ordering, official-URL/digest validation, actual HTTPS feed access and asset download, size/hash validation and corruption rejection. GUI smoke tests update-preference persistence. Linux packaging tests a silent update with a real wait-for-exit process and preserved project file; Windows packaging tests silent update, wait-for-exit, actual relaunch and clean shutdown before uninstallation.
